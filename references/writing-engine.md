# 写作引擎

## 输入锁定

开始正文前，整理一份事实卡：

- 本段在全篇中的功能；
- 视角人物、时间、地点和叙事人称；
- 开场状态、人物目标、阻力、转折、代价和结束状态；
- 每个角色此刻知道、误解和隐瞒的内容；
- 必须出现或保持不变的设定；
- 目标长度和与前后章节的接口。

事实卡控制“写什么”，作者画像控制“怎样写”。风格修订不得改变已经锁定的剧情事实。

## 匹配写作条件

从语料中选取与目标场景最接近的两到四个短样本，优先顺序是：

1. 相同视角人物或叙事距离；
2. 相同场景功能；
3. 相近的情绪强度与人物关系阶段；
4. 相近的章节位置。

长篇语料先用索引缩小范围：

```powershell
python .\scripts\corpus_index.py search .\work\corpus-index.jsonl --query-file .\draft-or-brief.txt --top 6 --include-text
```

再根据以上四项条件细读并留下两到四个样本。表层距离接近不能替代场景判断。

读取它们的证据卡和画像规则，提取写作机制。新文本沿用机制与变化范围，使用新故事自己的事件、物件、意象和句子。

## 场景风格简报

每个场景开始前确定：

- 镜头从哪里进入，叙述距离何时变化；
- 句子如何从常态进入压力，又如何在转折后改变；
- 每类段落承担动作、观察、对白、念头或信息中的哪一种功能；
- 当前角色说话的长度、主动性、回避方式和潜台词；
- 作者会优先注意哪些感觉与具体物件；
- 情绪通过哪种通道显现；
- 信息在何处提示、延迟、误导或揭示；
- 场景最后留下动作后果、关系变化、信息缺口还是意象回声；
- 本场景最适合使用的两到三种招牌动作。

## 分场景生成

1. 先写场景骨架，只列动作、信息和关系变化。
2. 按场景风格简报生成正文，让每段都对剧情、人物、气氛或信息至少承担一个明确功能。
3. 到达转折时重新检查叙事距离、句长变化和人物声音；作者的风格通常会随压力变化。
4. 场景完成后核对事实卡，修复时间、位置、知识状态和因果错误。
5. 长章节进入新场景或切换视角时，重新加载写作包与对应场景模式。

## 作者式修订

第一稿完成后按作者自己的优先级修订：

1. 调整叙述者与人物的距离；
2. 恢复段落推进和信息释放方式；
3. 让动作、观察、念头和对白按作者习惯排列；
4. 校准角色声音与关系中的潜台词；
5. 调整句子与标点，使节奏落入相同场景的常见范围；
6. 检查招牌动作是否自然出现并保持节制；
7. 删除没有场景功能、只是在解释已有信息的句子。

遇到画像规则冲突时，优先级是：当前场景和角色的条件规则 → 有强证据的稳定规则 → 表层统计范围 → 低可信度观察。

## 用户反馈回流

用户指出某段“像”时，记录具体起作用的机制与场景条件；指出“不像”时，定位是事实、视角、节奏、用词、对白、情绪还是结构偏差。把确认结果写回证据地图和漂移纠正表，不把一次反馈扩展成所有场景的绝对规则。
